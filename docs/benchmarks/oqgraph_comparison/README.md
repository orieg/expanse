# MariaDB OQGraph × Judy1: libexpanse as a drop-in for OQGraph's colour map

MariaDB's OQGraph storage engine (`storage/oqgraph/`, MariaDB `8e291917`) keeps a breadth-first or Dijkstra search's two-bit colour map in two Judy1 arrays, through its `judy_bitset` wrapper (`oqgraph_judy.cc`); the evaluation's audit of that source found OQGraph calling only the wrapper's `test()` and `set()`. This suite runs one MariaDB server build with four OQGraph plugins and times whole queries. It is the timed evaluation record behind the OQGraph row of the top-level README's [Verified in real projects](../../../README.md#verified-in-real-projects) table ([#1682](https://github.com/orieg/expanse/issues/1682)).

The record was measured by an earlier evaluation session and committed here afterwards. Nothing in this directory was re-measured to commit it.

The suite has no `/benchmark` token: its harness builds MariaDB and four plugin variants in a container, which the bare-metal workflow does not provide.

## Arms

| Arm | Plugin | Library mapped at run time |
|---|---|---|
| A | stock `Judy.h`, `-lJudy` (Ubuntu 24.04 `libjudy-dev` 1.0.5-5.1build1) | `libJudy.so.1.0.3` |
| B | Expanse's `Judy.h`, OQGraph source unchanged | `libexpanse.so` through a `libJudy.so` link |
| C | OQGraph ported to `expanse.h` (the native patch) | `libexpanse.so` |
| B1 | A's plugin binary, `LD_LIBRARY_PATH` pointing at `libJudy.so.1 → libexpanse.so` | `libexpanse.so` |

Every server start asserted the mapped library from `/proc/<pid>/maps` (`scripts/oqdrv.py`, `assert_libs`); each round's `libs` field in the raw rows records it.

**How `analysis.json` was produced.** The analysis file of the original session was not kept with the raw runs. The committed one was regenerated by the committed `scripts/analyze.py`, unchanged, from the committed raw rows. It is deterministic (10,000 resamples, seed 42): two regenerations are byte-identical, and every number in the 40 cell rows of the printed table equals the evaluation report's table.

**§8.17 disclosure.** Each raw row carries its load average and the host busy-CPU over its timed window, the busy-CPU delta §8.17 asks for. The rows do not carry the `provenance.host` and `estimators` blocks of `scripts/bench_provenance.py`, and the file names sit outside `check_bench_provenance.py`'s governed globs, so the gate does not check them. The host facts are in this README and in the pre-registration's Protocol section. The estimator is `scripts/bca_bootstrap.py` `bca_bootstrap_ci_with_method`, 10,000 resamples, seed 42, as pre-registered, and every interval records `ci_method` `bca`. `analyze.py` converts jiffies to core-equivalents with the host's 24 logical CPUs, a constant in the script. Before each run the host driver required three consecutive quiet checks (no containers, load1 < 1.5, busy < 0.5 core-equivalents) and held the host's bench lock throughout. Both runs report 0 void rounds under the pre-registered rule, and a busy-CPU median of 1.00 core-equivalent, the workload itself.

## Reproducing

The scripts run inside an Ubuntu 24.04 container with `/w` as the work directory. `scripts/build_base.sh` builds libexpanse and the stock MariaDB build, `scripts/build_variant.sh B|C` the two rebuilt plugins, `scripts/install_and_mtr.sh` installs the server and runs `mtr`, and `scripts/correctness.sh` and `scripts/reload_and_check.sh` the SQL comparisons. On the reference host, `scripts/go.sh` loads the datadir and calls `scripts/run_on_ref.sh`, which gates on a quiet host and runs `scripts/bench_ref.sh` twice, with order seeds 11 and 22. MariaDB's source is not committed; build it from `8e291917`. Then:

```bash
python3 docs/benchmarks/oqgraph_comparison/scripts/analyze.py scripts \
  docs/benchmarks/oqgraph_comparison/results/era_0_18_82eb56af/bench-run1.json \
  docs/benchmarks/oqgraph_comparison/results/era_0_18_82eb56af/bench-run2.json
python3 docs/benchmarks/oqgraph_comparison/scripts/summarize.py \
  docs/benchmarks/oqgraph_comparison/results/era_0_18_82eb56af
```

The first writes `analysis.json` to the current directory and prints `analysis.txt`; the second prints the summary above.

No independent, non-LLM review of this evaluation has been done.
