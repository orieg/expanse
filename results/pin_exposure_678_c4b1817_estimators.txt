# `perf stat` on a P-pinned process reports non-zero `cpu_atom/*` rows (and, on an E-pinned one, sometimes `cpu_core/*` rows).
# Whether the workload ran on the other class was checked directly with `perf record` on the other class's PMU:
#   $ perf record -e cpu_atom/cycles/ -F 2000 -- taskset -c 0-15 <domain bench> --bench raw_expanse_set_intersection/100000 --measurement-time 1 --warm-up-time 1
#   time: [10.770 µs 10.795 µs 10.818 µs]          (the P-core figure; the E-core figure for this arm is ~16.2 µs)
#   perf report --sort comm,cpu      -> 100.00%  taskset  (cpu unknown)
#   perf report --sort comm,dso,sym  -> every sample is the `taskset` launcher in ld-linux / the kernel, before it applied the mask; none is the bench binary
# The bench itself produced no E-core samples, and its criterion time is the P-core value. The `cpu_atom/*` rows `perf stat`
# prints for a P-pinned process are therefore not read as work on the E-cores; their cause is unknown (perf 6.8.12, Linux 6.8),
# and only the pinned class's own PMU rows above are used. An E-pinned run whose `cpu_core/*` rows read `<not counted>`
# (E3 rep 2, E4) is the clean case; the E-core rows of E3/E4 are the ones cited.
